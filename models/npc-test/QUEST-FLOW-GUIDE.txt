1. 한 줄 요약
--------------------------------------------------------------------------------
  의뢰인 NPC가 퀘스트를 준다 → 안개 계곡 조사(UE 연출) → 학자 알릭에게 보고
  → 엔진이 분기·보상 결정 → 알릭이 completionDialogue 로 반응한다.

  보고(turn-in)는 의뢰인에게 돌아가지 않는다. 수신 NPC = scholar_alric 고정.
  엔진 데이터에 없는 이름(예: 세계의 길잡이)은 UE UI 플레이스홀더 — npcs.json 표시명 사용.


2. 이 퀘스트가 말하는 이야기
--------------------------------------------------------------------------------
  배경
    안개 계곡에 밀수꾼들이 화물을 버리고 도망갔다는 소문이 돈다.
    화물 안에는 마약초 등 위험 물자가 들어 있을 수 있다.
    마을은 이 화물을 어떻게 처리할지—공식 인도 vs 암시장 유입—결정해야 한다.

  플레이어 역할
    현장에 가서 직접 확인하고, 플레이어의 텍스트 입력으로 조사 결과를 보고한다.
    같은 현장이라도 「누구에게 의뢰받았는지」에 따라 보고가 다르게 해석될 수 있다.

  핵심 갈등
    · 브리핑 때 NPC는 과장·소문으로 말할 수 있다 (연출).
    · 실제 판정은 플레이어가 입력한 「조사 보고」만 엔진이 해석한다.
    · 해석 결과(수량·확신)에 따라 화물 행선과 보상이 갈린다.

  한 줄 플롯
    소문의 화물을 조사해 학자 알릭에게 보고한다.
    보고가 크고 확실하면 관청(authority), 작고 애매하면 암시장(black_market) 쪽으로 흐른다.


3. 등장인물
--------------------------------------------------------------------------------
  플레이어 (카엘)
    현장 조사·보고를 직접 수행하는 주인공.

  의뢰인 — 퀘스트를 맡기는 NPC (플레이어가 택 1)
    guard_timid      소심한 경비   — dramatic, 수량 과장 경향
    merchant_greedy  탐욕한 상인   — dramatic, 소문·이익 중심
    scholar_alric    학자 알릭     — faithful, 사실·숫자 중시

  보고 수신 — 항상 scholar_alric (학자 알릭)
    경비·상인에게 의뢰받아도 최종 보고는 알릭에게. 알릭이 기록·처분 근거가 됨.

  (선택) 퀘스트 허브 도입 — 학자 알릭 introDialogue
    "안개 계곡에 버려진 화물 소문이야. 경비·상인·내 관점 중 누구 일로 맡을지 정해."


4. 플레이어가 겪는 단계
--------------------------------------------------------------------------------

  ┌─────────────────────────────────────────────────────────────┐
  │ ① 의뢰 수락    의뢰인 NPC와 대화 → 퀘스트 수락 + 브리핑      │
  │ ② 현장 조사    안개 계곡 이동 → 화물·상자 확인 (게임 연출)   │
  │ ③ 조사 보고    학자 알릭에게 한국어로 결과 보고 (자유 입력)  │
  │ ④ 결과 반영    엔진 분기·보상 → 알릭 완료 대사·세계 상태 변화 │
  └─────────────────────────────────────────────────────────────┘

  엔진 파이프라인 (③에서 실행)
    플레이어 한국어 보고 → 파서(facts[]) → 엔진 해석(interpretedFacts)
    → 퀘스트 분기·보상
    ※ LLM은 판정 경로에 끼지 않음. 대사 연출만 담당 가능.

  UE 매핑
    [1] F 대화 — 의뢰인 | acceptDialogue + 브리핑 | SaveGame: questId, giverId
    [2] 안개 계곡 — travel | 맵·오브젝트 연출만 | 엔진 대사 없음
    [3] F 대화 — 알릭 | scenarioText 입력 | POST /v1/quest/turn-in
    [4] 결과 — 알릭 | completion.completed == true 일 때만 완료 대사·골드

  ★ 완료 판정 (UE·웹 데모 공통 — 가장 중요)
    processSteps 를 다 밟았다고 완료가 아님.
    turn-in 응답의 completion.completed === true 일 때만:
      · completionDialogue 재생
      · 골드·worldFlags 반영
      · QuestState.completed = true
    completion.completed === false 이면:
      · 실패 대사 (completion.reason 참고, 예: subject missing 마약)
      · 골드 0, 완료 배너·완료 대사 금지
      · activeQuest.state = turn_in_failed (웹 데모 기준)
    HTTP 200 / ok: true 라도 completion.completed 가 false 면 실패 처리.

6. 의뢰인을 바꾸면? (같은 현장, 다른 느낌)
--------------------------------------------------------------------------------

  공통: 조사는 똑같이 안개 계곡. 보고는 똑같이 알릭에게.

  ┌──────────────┬─────────────────────┬──────────────────────────┐
  │ 누가 의뢰?   │ 처음에 뭐라고 함?   │ 12개 보고했을 때         │
  ├──────────────┼─────────────────────┼──────────────────────────┤
  │ 소심한 경비  │ "위험할지도 몰라…"  │ 15개로 해석 → 150골드   │
  │              │ "마약초 잔뜩일 거야"│ 관청으로                 │
  │              │                     │ 알릭: "당장 기록하겠네"  │
  ├──────────────┼─────────────────────┼──────────────────────────┤
  │ 탐욕한 상인  │ "값나가는 건 내가…" │ 15개로 해석 → 150골드   │
  │              │ "금빛 상자, 많이…"  │ (경비와 같은 결말)       │
  │              │                     │ 알릭: "기록해 두지"      │
  ├──────────────┼─────────────────────┼──────────────────────────┤
  │ 학자 알릭    │ "숫자는 정확히"     │ 12개 그대로 → 150골드    │
  │              │ "규모를 확인하게"   │ 알릭: "수고했네"         │
  └──────────────┴─────────────────────┴──────────────────────────┘

  포인트: 해석 숫자(15 vs 12)는 달라도, 규칙상 둘 다 「많은 편」이면
          같은 보상·같은 결말(150골드, 관청)이 나올 수 있다.


7. 결말이 갈리는 기준 (쉬운 말로)
--------------------------------------------------------------------------------

  「많다」고 판단되면
    → 화물이 관청으로 / 150골드
    → 알릭: "당장 기록하겠네" 류

  「적다」고 판단되면 (예: 마약초 5개만 보고)
    → 화물이 암시장으로 새어 나감 / 300골드
    → 나레이션: "암시장 쪽으로 새었다"

  애매하면
    → 80골드 / 행선 불명

  보고가 엉뚱하면 (예: "아무거나", "오늘 날씨가 좋다")
    → completion.completed = false / 골드 없음 / 완료 대사 없음
    → 실패 사유 예: subject missing 마약

  보고가 비어 있으면
    → turn-in 자체를 보내지 않음 (UE·웹 모두 입력 필수)

  최소 통과 조건 (factMatch, 둘 중 하나)
    · subject 에 「마약」 포함 + 수량·확신 하한 충족
    · 또는 subject 「화물」+ target 「계곡」 (factMatchAlt)
    ※ 「마약」 한 단어만으로도 통과할 수 있음 — 데모용으로 느슨함.
    ※ 기본 예시 문장 전체를 그대로 두고 글자만 추가하면 통과함 → 입력란은 비운 뒤 작성.


8. 꼭 기억할 것 4가지 (발표용)
--------------------------------------------------------------------------------
  1) 경비가 "잔뜩일 거야"라고 해도, 진짜 판정은 플레이어가 친 보고문이다.
  2) 같은 12개 보고도 의뢰인에 따라 15 vs 12로 해석되지만, 결말이 같을 수 있다.
  3) 보고할 때 플레이어가 친 글자가 화면에 보여야 한다 (입력 증거).
  4) 완료는 completion.completed 로만 판단 — 단계 진행·HTTP ok 와 무관.


9. 발표·데모에서 보여줄 두 가지
--------------------------------------------------------------------------------

  【시나리오 A — 메인】 경비 의뢰 + 12개 보고
    1. 경비 만나서 의뢰 받기
    2. (생략 가능) 계곡 조사
    3. 알릭에게 12개 보고 입력 → 실행
    4. 150골드, 관청 인도, 알릭 완료 대사

  【시나리오 B — 한 줄만】 학자 의뢰 + 5개 보고
    → 적게 보고하면 암시장 루트, 300골드 (분기가 바뀐다는 증거)

  【시나리오 C — 실패 증거】 경비 의뢰 + 엉뚱한 보고
    1. 보고란에 "아무거나" 만 입력 (기본 예시 문장 남기지 말 것)
    2. 퀘스트 실행
    3. 「보고 실패」 표시, 골드 변화 없음, completion.completed = false
    → 「아무 말이나 치면 완료」가 아니라 엔진이 factMatch 로 거른다는 증거


  ── 부록: 경비 수락 대사 (평판에 따라 바뀜) ──
    기본(보통): "계곡 화물? 위험할지도 몰라… 네가 대신 확인해줘."
    우호:       "자네라면 믿을 수 있지. …정확히 파악해서 나에게만 먼저 알려주게."
    신뢰:       "지금 마을 안전을 위협하는 화물 정보가 급히 필요하네."
    (API로 가져오기: GET /v1/quest/accept-dialogue?giverId=guard_timid)


10. Turn-in API (UE 보고 시 필수)
--------------------------------------------------------------------------------
  POST http://127.0.0.1:8787/v1/quest/turn-in

  {
    "questId": "quest_abandoned_cargo",
    "giverId": "guard_timid",
    "scenarioText": "안개 계곡에 밀수 화물이 버려져 있다. 마약초 열두 개가 들어 있다",
    "sessionKey": "player-save-slot-1"
  }

  giverId      = 퀘스트를 준 의뢰인 (수락 시 선택)
  scenarioText = 플레이어 조사 보고 (한국어)
  UI 화자      = 보고 시 scholar_alric (학자 알릭)

  응답 필드
    completion.completed   ← 이것이 true 일 때만 아래 반영
    completion.reason      실패 시 사유 (예: subject missing 마약)
    outcomeBranch.branchId
    outcome.rewards.gold
    outcome.worldFlags.cargo_destination

  UE 반영 순서
    if (response.completion.completed) {
      골드·worldFlags·completionDialogue·QuestState.completed = true
    } else {
      실패 UI만 — 골드·완료 대사 금지
    }
    ※ HTTP 200 이고 body.ok === true 여도 completion.completed 가 false 면 실패.

  상세 HTTP·SaveGame: INTEGRATION-GUIDE.txt


11. 플레이어 입력 UI — 반드시 눈에 보여야 함
--------------------------------------------------------------------------------
  핵심: 자유 한국어 보고가 화면에 보여야 「정해진 대화 트리」 오해를 막을 수 있음.

  현재 gap
    UE: NPC 출력만 (세계의 길잡이 placeholder)
    웹 데모: textarea 가 폼 상단 — 대화창과 분리 (대화형 UI는 미구현)

  웹 데모 (index.html, 2026-06-11)
    · 보고란: 비어 있음 + placeholder 예시 (미리 채운 기본문 없음)
    · 성공: 초록 「퀘스트 완료」 배너 + 결과 카드
    · 실패: 빨간 「보고 실패」 배너 + completion.reason
    · Ctrl+F5 로 캐시 무시 새로고침 권장

  권장 UI (보고 단계 — 알릭)
    [알릭] "조사 결과를 말하게."
    [플레이어 말풍선] 제출한 scenarioText 그대로 표시
    [입력칸 + 보고 버튼] 타이핑 노출
    [알릭] completionDialogue

  단계별 입력
    의뢰: NPC 대사만 + 「수락」 버튼 (자유 입력 없음)
    조사: 환경 자막만
    보고: 플레이어 텍스트 입력 필수


12. UE 위젯 체크리스트
--------------------------------------------------------------------------------
  [ ] 의뢰: 화자 = 의뢰인, GET accept-dialogue
  [ ] 브리핑: processSteps[0].npcLine
  [ ] 계곡: 오브젝트·자막 연출만
  [ ] 보고: 화자 = 알릭, 입력칸 + scenarioText → turn-in
  [ ] 완료: completion.completed == true 일 때만 알릭 completionDialogue + 골드
  [ ] 실패: completion.completed == false → 실패 대사, 골드·완료 연출 금지
  [ ] 임시 NPC명 → npcs.json displayName
  [ ] 제출 후 플레이어 말풍선에 보고문 고정
  [ ] 보고 구간 단방향 NPC-only UI 금지
  [ ] 발표 녹화: 입력 → 제출 → 결과 한 흐름
