1. 프로젝트 목적
--------------------------------------------------------------------------------
  캡스톤 게임(Project-Nova)용 NPC 정보 시스템의 브라우저·Node 프로토타입.

  - 플레이어가 입력한 문장을 파서가 facts[] 로 분해
  - 결정론 엔진이 발신·수신 NPC 성향·평판에 따라 왜곡·해석
  - NPC/LLM이 보는 "진실"은 interpretedFacts 뿐 (원문·파서 fact 직접 사용 금지)
  - 퀘스트 완료·보상·분기는 interpreted 수량·확신 기준

  언리얼 C++ 게임 엔진이 아니라, UE에 붙일 "두뇌"를 검증하는 샌드박스다.


2. 설계 원칙 (합의·구현됨)
--------------------------------------------------------------------------------
  (1) 동일 입력·동일 스탯·동일 신뢰 → 동일 왜곡·동일 applied_rules
  (2) NPC가 믿는 정보 = 전파·해석 이후 interpretedFacts
  (3) LLM = 말투·연출만, 사실 생성·추측 금지 (mock 기본, live 선택 가능)
  (4) 퀘스트 분기 = outcomes[] (authority_path / black_market_path / fallback)
  (5) 평판 두 층:
      - NPC 주제별 reputation (npcs.json) → 왜곡 엔진
      - 플레이어↔NPC reputation (reputation-config + reputation-system.js)
        → 의뢰 대사 tier, defaultTrustToPlayer 보정


3. 퀘스트 방향 전환 (완료)
--------------------------------------------------------------------------------
  [이전]  늑대 탈출·북문 등 프로토타입 퀘스트 (quest_report_wolf_escape 등)
  [현재]  정식 퀘스트 1개만 활성:

    quest_abandoned_cargo — "밀수업자의 버려진 화물"

  - 의뢰인: guard_timid (dramatic) / merchant_greedy (dramatic) / scholar_alric (faithful)
  - 보고 대상(turn-in): scholar_alric
  - 기본 보고문 예:
      "안개 계곡에 밀수 화물이 버려져 있다. 마약초 열두 개가 들어 있다"

  - outcomes[]:
      authority_path   : interpreted qty ≥ 10, certainty ≥ 0.6 → gold 150, cargo→authority
      black_market_path: interpreted qty ≤ 9, certainty ≥ 0.4  → gold 300, cargo→black_market
      outcomeFallback  : 그 외 중간값 → gold 80, destination unknown

  - quests-draft.json 에서 _archivedQuests(늑대·반군) 제거
  - 회귀 테스트·distortion/integration 케이스 → 안개 계곡·마약초·밀수 테마로 정렬


4. 구현 완료 항목
--------------------------------------------------------------------------------

4.1 핵심 엔진 (quest-system.js)
  - distortInformation / reinterpretInfo / propagateFactBundle
  - KnowledgeBase merge, bundle 모순(같은 장소 위협 vs 태연), session persist
  - persistSession 시 receiver KB 유지, F01 info_id 충돌 시 mergeKey 기반 storageId 분리
  - placeTokens에 "안개 계곡" 추가
  - BUILTIN_PROFILE_REGISTRY = npcs.json 과 동기 (guard_timid / merchant_greedy / scholar_alric)

4.2 파서 (app.js + dictionaries.js)
  - 한국어 복합문, 수량(열두 개 등), rumor, state/tactical 분류
  - 빈 입력 기본값: 밀수 화물·안개 계곡 (늑대 기본값 제거)
  - test-cases.json: cargo 스위트 + legacy 파서 회귀 병행

4.3 퀘스트 런타임 (quest-runtime.js)
  - loadQuestCatalog, factMatch / factMatchAlt, pickOutcomeBranch
  - runQuestTurnIn (플레이어 발신 → scholar_alric 수신)
  - resolveAcceptDialogue: neutral tier → 의뢰인별 acceptDialogue (3색)
                      hostile/trusted 등 → sharedAcceptDialogueByTier
  - acceptQuest / advanceProcessStep / runQuestFlow (스텝별 진행)
  - runProcessSteps (한 번에 3스텝 + turn-in)

4.4 로컬 게임 상태 (quest-game-state.js) — UE 대체 데모
  - gold, xp, villageReputation, worldFlags, questHistory
  - runQuestTurnIn / runQuestFlow 완료 시 applyTurnInOutcome
  - exportState / importState (세이브 슬롯 연동 전 로컬 스냅샷)

4.5 평판 (reputation-system.js + JSON)
  - tier: hostile / wary / neutral / friendly / trusted
  - 퀘스트 완료 playerRepDelta (village, current_giver, npc 키)
  - reputation-config fallback 키 → cargo NPC 3명으로 통일

4.6 NPC·플레이어 프로필 JSON (v3 정리)
  - npcs.json: 주제 reputation 확장(밀수, 화물, 마약초, 안개 계곡, 도적), propagationPreset
  - player-profile.json: initialNpcReputation ↔ config default 일치
  - reputation-config.json: questRole, turnInTarget 메타
  - data-loader.js: npcs + player + reputation setConfig
  - profiles-sync-test.mjs: 세 파일 키·default 검증

4.7 LLM (llm-adapter.js, llm-settings.js)
  - mock 기본
  - OpenAI / Anthropic / compatible live 경로 (API 키는 localStorage 또는 llm-config.local.json)
  - 입력은 interpretedFacts → [Grounded DATA] 만

4.8 브라우저 UI (index.html + runner 스크립트)
  - Scenario Controls: usePlayerAsSender 기본 ON, scholar 수신, 의뢰인 quantityMode 프리셋
  - Quest Playtest:
      Accept Quest / Next Step / Run Full Flow / Turn-In Only / Compare Givers
      Game State 패널, Process Steps, 의뢰 대사 미리보기
  - Parser / Distortion / Integration 인브라우저 회귀 버튼
  - Reputation 패널

4.9 문서·도구
  - README.md, ENGINE-DESIGN.txt, GAME-API.json (UE 연동 계약만, 코드 없음)
  - package.json (npm test → run-all-tests.mjs)
  - cargo-slice-report.mjs (high/low × 3 의뢰인 리포트)

6. 의뢰인별 동작 요약 (검증됨)
--------------------------------------------------------------------------------
  동일 고수량 보고문(마약초 12개) 예:
    guard_timid / merchant_greedy (dramatic) → qty 약 15, authority_path, gold 150
    scholar_alric (faithful)                 → qty 약 12, authority_path, gold 150

  저수량 보고문(마약초 5개) + scholar_alric:
    → black_market_path, gold 300

  의뢰인별 processSteps npcLine = 브리핑(3색 소문) 연출용 데이터
  neutral 수락 대사 = giver.acceptDialogue 각각 다름
